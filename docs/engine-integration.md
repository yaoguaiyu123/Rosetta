# PDFMathTranslate-next 接入记录

日期：2026-10-01，分支：`feat/html-typesetting`。

## 改动

- 删除 `fullTranslation.ts` 与 `fullHtml.ts`，以及服务器的旧字体嵌入、PDF 保存、HTML 打印接口，移除 pdf-lib/fontkit 依赖。
- 新全文链路：浏览器上传原文 → 本机 Node 任务服务 → 独立 Python 的 PDFMathTranslate-next → mono/dual 成对保存 → PDF.js 显示原生输出。
- Python 任务使用设置中的同一个翻译接口及模型；配置通过 stdin 传入，不放进命令行和任务文件。日志不保存 API Key 或全文内容。
- 引擎独立运行；任务进度可查询，取消时结束 Windows 子进程树。原文限制在 Python 入口再次校验，超过 40 页在调用模型前拒绝。
- 缓存按原文 SHA-256 及引擎版本查找完整配对。重新翻译跳过文字翻译缓存，PDF 与索引一起更新；错误回滚。取消或失败不删除原有译本。
- 支持自定义输出目录和写入失败回退。不同原文同名时保存为不同指纹文件名。
- 旧评估目录的六份译本可通过原文内容验证复用；旧浏览器排版的单版文件不覆盖、不冒充引擎结果。
- 暗色界面重新设计：两层工具栏、模式分段按钮、欢迎页、译文面板、进度条、阅读状态栏、设置弹窗与窄屏布局。
- 解决隐藏阅读器的页码事件干扰当前视图，以及取消旧 PDF.js 文字层后出现空白页和虚假错误的问题。
- 缩放保留页码和页内阅读位置；跳页或切换文档时作废旧的缩放位置恢复，避免异步回调把阅读器拉回第一页。
- Windows 上实测 Node 24.11.1 的 `fs.rmSync` 未实际清理测试文件，改用带目录范围校验的 unlink/rmdir 清理。

## 验证证据

- `npm run type-check` 和 `npm run build` 通过。
- `npm run setup:engine` 在现有环境重新执行成功。
- 四项本地服务回归测试通过：原文指纹与配对复用；重新翻译替换两个文件；失败与取消保留旧文件且清理临时原文；自定义目录不可用时回退。测试不调用外部模型。
- 通过实际本机任务接口重新翻译 Attention 全部 11 页，验证两个真实 PDF 的页数、dual 宽度、保存路径、返回内容与磁盘文件逐字节相同，再次创建时直接复用。
- 使用真实 Python 子进程验证取消：临时原文删除，无成品输出，任务名额释放。该取消测试使用本地不可用模型地址，没有调用外部模型。
- 使用 417 页教材验证 Python 入口的页数限制，返回超过 40 页错误，不调用翻译模型。
- 浏览器中用 MobileNetV3 的已保存译本检查中英/中文切换、第 3 页保留、划词/全文模式往返保留译本、设置弹窗、窄屏适应宽度后仍保留第 3 页。检查真实 canvas/textLayer 渲染，而非仅检查按钮文本；本次浏览器验收没有发出翻译请求。
- 重新翻译的 PDF 做渲染检查；UI 做截图检查。该检查验证接入和显示，没有逐一证明全文所有公式和表格数据等价。

## 保留的限制

本次接入使用已经评估过的原生引擎输出，没有修补上游的版面语义识别。标题、作者、参考文献及部分图表文字可能仍被翻译；少数行内公式的数学结构仍有错误。
这些是 [之前的引擎评估](pdf2zh-next-evaluation.md) 中已经确认的问题，本次不是公式质量验收通过的声明。

中英对照现在是一个 dual PDF 页面，两边随同一份 PDF 滚动，按本次明确要求实现。中文字号采用引擎默认原位排版策略。

## 浏览器回归脚本

`.workbuddy/tools/verify-engine-reader.mjs` 需要一个已有完整 mono/dual 配对且至少三页的 PDF。
先启动本机服务与独立浏览器调试实例，再指定 `APP_URL`、`CDP_PORT`，传入 PDF 路径和截图前缀。
脚本只打开已有配对，不触发全文翻译；打开设置会查询当前模型列表。
