# 0.1.4 阅读画面连续性

## 原因与修复

旧版离开 800 像素预加载范围后立即清空页面，高亮、橡皮擦和撤销也会清空所有页面后重画。清空后的容器是白底，因此绘制尚未完成时会出现全白页。

新版保留旧画面，在屏幕外完成绘制后一次替换；编辑只更新受影响的页面，同一缩放下保留文字层。滚动优先绘制可见页，并根据方向预加载，每个阅读区同时最多两项绘制。

清晰画面缓存按 96 MiB、12 页控制；可见页和正在绘制的页优先保留。淘汰清晰画面时留下小预览，预览另按 16 MiB、48 页控制，并保留页面护眼色调。返回时先显示预览，再换清晰画面。首次到达尚未绘制的页会显示与暗色主题一致的加载提示。极大页面单张画布限制为约 1200 万像素。

这些限制针对页面位图，不等于整个浏览器的内存上限；可见页面、绘制中的临时画布、PDF.js 解析数据和文字层仍需内存。

## 复测

使用引擎 Python 运行 `scripts/create-reader-test-fixture.py` 生成自建的 30 页测试文档，再执行：

```sh
npm run build
node scripts/verify-reader-rendering.mjs
```

测试需要 Windows Edge、Node.js 和已存在的测试 PDF；可用 `--fixture`、`--dist`、`--output` 指定路径。复测旧版时额外传入 `--baseline --baseline-dist <旧版dist目录>`。脚本使用独立配置和浏览器目录，阻止翻译接口，不读取用户配置、不调用真实模型。

逐帧检查包括高亮、新高亮擦除、已有高亮擦除、撤销擦除、保存、快速来回滚动和缩放。还会翻到第 30 页制造缓存淘汰，检查小预览及色调，返回首页确认没有白帧。保存结果另外用 PyMuPDF 重新打开检查标准批注及原文。

2026-10-21 在同一测试文档、浏览器 CPU 减速 4 倍的条件下，旧版在上述编辑及滚动场景都记录到了白帧；新版对应场景为 0。缓存压力检查中保留 12 张清晰画面、18 张预览，位图约 31.7 MiB。该结果代表本机复测样例，不代表所有 PDF 和所有设备的耗时保证。
